# GitHub Branch Protection & CI/CD Requirements

This document outlines the GitHub branch protection rules and CI/CD quality gates for `main` branch in **PulseBoard**.

---

## 🛡️ Main Branch Protection Setup

To enforce branch protection on GitHub:

1. Navigate to your repository on GitHub: `Settings` -> `Branches`.
2. Under **Branch protection rules**, click **Add branch ruleset** or **Add rule**.
3. Set **Branch pattern name** to `main`.

---

## ⚙️ Mandatory Protection Settings

### 1. Require Pull Request Before Merging

- [x] **Require a pull request before merging**
- [x] **Require approvals**: Minimum 1 approving review from a code owner / peer reviewer.
- [x] **Dismiss stale pull request approvals when new commits are pushed**
- [x] **Require review from Code Owners**

### 2. Require Status Checks to Pass Before Merging

- [x] **Require status checks to pass before merging**
- [x] **Require branches to be up to date before merging**

#### Required Status Checks:

Search and select the following status check names generated by `.github/workflows/ci.yml`:

- `Code Quality (Node 20.x)`
- `Code Quality (Node 22.x)`
- `Unit Tests & Coverage (Node 20.x)`
- `Unit Tests & Coverage (Node 22.x)`
- `Build Application & Storybook`
- `Playwright E2E Tests`

### 3. Commit & Merge Restrictions

- [x] **Require linear history**
- [x] **Include administrators** (Enforce rules for repository admins)
- [x] **Restrict who can push to matching branches** (Only merged PRs allowed)

## 📊 CI/CD Pipeline 10-Stage Architecture

| Stage  | Name                | Trigger / Tool                                | Fail Criteria                                         |
| ------ | ------------------- | --------------------------------------------- | ----------------------------------------------------- |
| **1**  | **Install**         | `npm ci` (Node 20 & 22)                       | Dependency resolution / lockfile mismatch             |
| **2**  | **Type check**      | `npm run typecheck` (`tsc -b`)                | TypeScript compilation errors                         |
| **3**  | **Lint**            | `npm run lint` (`eslint .`)                   | ESLint errors or syntax issues                        |
| **4**  | **Format check**    | `npm run format:check` (`prettier --check .`) | Unformatted code style                                |
| **5**  | **Unit tests**      | `npm run test` (`vitest run`)                 | Any failing unit / component test                     |
| **6**  | **Coverage**        | `npm run test:coverage`                       | Coverage drop below thresholds (70% lines/statements) |
| **7**  | **Build**           | `npm run build` (`vite build`)                | Vite build failure or missing assets                  |
| **8**  | **Storybook build** | `npm run build-storybook`                     | Storybook compilation failure                         |
| **9**  | **E2E tests**       | `npm run test:e2e` (`playwright test`)        | E2E user flow test failure                            |
| **10** | **Deployment**      | CI CD Deployment Job                          | Production deployment trigger failure                 |
